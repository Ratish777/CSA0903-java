# CO4 – Event-Driven GUI Design

## Task 1 – Fee-payment window review
Defects: all logic is inside the frame/listener (poor separation); `==` compares String references instead of content; empty/non-numeric/negative amount is not validated; JDBC runs on the event-dispatch thread and `sleep(3000)` freezes repaint/input; SQL concatenation permits injection; connection/statement are not closed; checked exceptions are not handled; receipt button has no implementation; no success/error dialog or status; no window-closing handling. Repair: UI reads fields and displays status; `FeeService` validates and performs parameterized database operation; execute long work in `SwingWorker`; use try-with-resources; `equals()` for command comparison. Separate button listeners or Swing `Action`s avoid an if/else chain; dispatch is O(1) direct listener routing versus up to O(k) command checks; k listener objects use O(k) small references/objects. Separation allows service unit tests without opening a window.

## Task 2 – Appointment desk
Event table: department JComboBox → ActionEvent/ActionListener → load matching doctors from `Map<String,List<Doctor>>`; doctor JComboBox → ActionEvent → refresh available time slots; Book JButton → ActionEvent → validate patient ID/department/doctor/slot, invoke service, show confirmation/error; window close → WindowEvent/WindowListener → if booking active ask confirmation else dispose. Containment: JFrame → root JPanel(BorderLayout) → form JPanel(GridLayout) containing labels/fields/combos; button panel FlowLayout; status JLabel. Pseudocode: on department change clear doctor/time models, add doctors from map, select first if present; on book validate fields, set bookingInProgress, call service asynchronously, display result, reset flag. Startup: construct components, register listeners, pack/show; closing invokes windowClosing then dispose. Applet lifecycle `init/start/paint/stop/destroy` is distinct from desktop window events. Cached map costs O(d+m) space and avoids repeated DB round trips; querying each change costs DB latency each time.

## Task 3 – Library search layout
Use root BorderLayout: title NORTH, search row FlowLayout NORTH inside a panel, results JScrollPane CENTER, navigation buttons FlowLayout SOUTH, status SOUTH (or a nested bottom panel with buttons and status). CENTER expands on resize; FlowLayout preserves preferred button sizing. Nested panel tree: JFrame(BorderLayout) → title JLabel(NORTH), search JPanel(FlowLayout), results JScrollPane(CENTER), bottom JPanel(BorderLayout) → controls JPanel(FlowLayout CENTER) and status JLabel(SOUTH). GridBagLayout offers flexible constraints but more setup; absolute positioning breaks resizing/font scaling. Layout traversal is approximately O(c) for c components; nested panels add O(c) component/container memory.

## Task 4 – Drawing pad
The method is misspelled `mouseclicked`; Java listener method is `mouseClicked`, so it is never overridden. Direct `getGraphics()` drawing is transient and lost after repaint/minimise/restore. Store each `Point` in a list, update label, call `repaint()`, and draw all points in `paint(Graphics)`. `@Override` causes a compile-time error if the method name/signature is wrong. Completed code is in `Task04/DrawPad.java`. For n points, repaint loop is O(n), storage O(n); an off-screen BufferedImage costs O(width×height) pixels but repaint can copy the image in O(width×height) pixel work and drawing occurs only on click.

## Task 5 – Event-handler styles
Use named listener classes when reusable/stateful, anonymous classes for one-off handlers, lambdas for functional listener interfaces. Adapter classes avoid implementing unused methods of multi-method listeners. Keep handlers short and delegate to service methods. Direct listener registration is easy for small fixed forms; Swing `Action` centralises action name, icon, enabled state and accelerator when reused by buttons/menus. Compare using testable requirements and maintainability, not syntax alone.

## Task 6 – Campus event registration design
Layers: `RegistrationFrame` (JFrame/JPanel/JTextField/JComboBox/JTable/JMenuBar) → `RegistrationService` (validate, duplicate policy, pagination/export) → `RegistrationDao` (JDBC). SQL table: `registrations(id BIGINT PRIMARY KEY AUTO_INCREMENT, student_id VARCHAR(30) NOT NULL, event_id BIGINT NOT NULL, registered_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP, UNIQUE(student_id,event_id))`. Register uses PreparedStatement and handles duplicate-key error; Filter uses `WHERE event_id=? ORDER BY registered_at LIMIT ? OFFSET ?`; export writes selected rows. Run DB work in SwingWorker so EDT remains responsive. Loading all 100,000 rows uses O(n) memory and delays initial display; pagination uses O(pageSize) client memory and bounded query results, though repeated pages add round trips. SQL script is in `Task06/schema.sql`; JDBC URL/user/password are placeholders and must be configured locally.
